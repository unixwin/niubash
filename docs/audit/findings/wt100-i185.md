### 6. fzf key-bindings.bash gate (acceptance)

Stub `fzf` (echoes `cargo build`) + the `__fzf_history__` CTRL-R subset
(real fzf structure: pipe candidates, `--query="$READLINE_LINE"`,
`READLINE_LINE="$output"; READLINE_POINT=${#READLINE_LINE}`, and
`bind -m emacs-standard -x '"\C-r": __fzf_history__'`).

- before: `bind -x` accepted silently; \C-r swallowed; no READLINE_* (artifacts
  `niu-bindx-before-*`).
- after (ConPTY, `niu-fzf-final-*`): source at prompt → press \C-r on line `AB`
  → `__fzf_history__` runs, reads `READLINE_LINE=AB`, stub prints `cargo build`,
  editor buffer becomes `cargo build` with cursor at end → Enter executes a
  **real cargo build** (`Finished dev profile`). Plumbing is fzf-ready; the real
  fzf.exe rides the same path (it is just the child process of the bind -x
  command).
- Same session verified: macro insert (`foo\C-t` → `fooins-macrobar`),
  function bind to accept-line, `--rcfile` startup registration, dumb
  write-back (`FIRED` + `landed`).

## Fixes landed

Engine (rubash, branch `wt100/i185`):

1. `src/shell/bind_registry.rs` (new) — process-global binding registry
   (function/macro/bind -x entries, per-keymap, generation counter), shared
   across ShellState clones like GNU's process-global readline keymaps.
2. `src/builtins/bind.rs` — rewritten as the pure grammar/format layer:
   isolate_sequence port (`bind -x` argument grammar), inputrc binding parser,
   inputrc file parser, GNU listing formats (-X/-s/-S/-p/-P/-q), error texts.
3. `src/executor/bind_builtins.rs` (new) — full `bind` dispatch (flags
   `-l p P v V s S X f: q: u: m: r: x:` with GNU order and rc semantics),
   registry mutations, and `Executor::run_bind_x_command` implementing the
   bashline.c:4593 READLINE_* protocol (set exported → parse_and_execute
   analog → read back clamped → unbind).
4. `src/shell/state.rs` / `src/executor/init.rs` / `src/executor/mod.rs` /
   `src/executor/job_builtins.rs` — ShellState field (shared Rc), init,
   module wiring, old validate-only stub dispatch removed.

Product (niubash, this repo):

5. `crates/niubash-runtime/src/shell.rs` — `load_engine_bindings` snapshot +
   `run_bind_x_command(index, buffer, cursor)` bridging reedline byte-offset
   cursor ↔ GNU char-offset READLINE_POINT, GNU read-back semantics
   (maybe_make_readline_line / point override / clamp), never accepts.
6. `crates/niubash-runtime/src/repl.rs` — engine bindings mirrored into
   reedline keymaps (bind -x → `__niu_bindx <i>` sentinel, macro →
   InsertString, known functions → event table; unknown/multi-key skipped with
   a one-time warning); keymap rebuild when the registry generation moves;
   GNU `\C-`/`\M-` keyspec parsing; **and the load-bearing fix: reedline 0.50
   delivers `ReedlineEvent::ExecuteHostCommand` as `Signal::HostCommand`
   (enums.rs:38-42), which the REPL loop dropped in `Ok(_) => continue` —
   the wt93 `__niu_widget` sentinel path was dead at the REPL layer; both
   sentinels now route through the shared `run_host_sentinel` handler.**

Gates: rubash lib 617 green (592 baseline + 25 new pinned tests), 0 warnings,
`-D warnings` clean, fmt applied. niu: runtime lib 374 green (6 new pinned
tests), workspace suites green, 0 warnings, `-D warnings` clean, fmt applied.
Note: the niu commits build against the rubash `wt100/i185` engine branch
(run `run_bind_x_command` / `bind_registry_snapshot` / `bind_registry_generation` /
`bind_editing_mode` exist only there); until the engine branch merges, the
`[patch."https://github.com/unixwin/rubash.git"]` line in `Cargo.toml` needs to
point at a rubash checkout containing it (the lane used
`path = "../rubash-wt-i185"`).

## Handoff list (product / upstream lanes)

1. **inputrc startup read** (~/.inputrc / $INPUTRC): loader translating the
   honored subset (key bindings, `set editing-mode`, `$if term=/mode=`) into
   the engine registry at startup — product lane; registry APIs are ready.
2. **readline variable table** (`bind -v`/`-V`, `set keymap`, `set
   completion-ignore-case`...): needs a real variable table in the product
   editor; engine prints nothing today rather than fake data.
3. **`bind -p`/`-P`/`-l` full-table fidelity**: 25-55 entries vs GNU 176 —
   grows automatically as the product event table grows; the engine list is
   the honest supported set.
4. **Multi-key sequences** (`\C-x\C-f`, `\e\e`) and bracketed-paste
   (`\e[200~`) bindings: reedline 0.50 `Keybindings` maps single
   `(KeyModifiers, KeyCode)` only (`edit_mode/keybindings.rs:45`). Upstream
   feature request (chord state machine) or product-side key sequencer.
5. **READLINE_ARGUMENT** (numeric prefix argument to bind -x commands):
   reedline has no numeric-arg concept — upstream.
6. **vi mode switching binds** (`vi-editing-mode`/`emacs-editing-mode` events,
   `set -o vi` reach-through): niubash#184 / wt101 lane; the registry records
   the names today.
7. **exit-status-124 forced redraw**: engine returns the status in
   `BindXRunOutcome`; reedline always repaints after the widget, so niu
   currently does not distinguish — only matters for full-screen plugins
   (rare; note kept for parity work).
