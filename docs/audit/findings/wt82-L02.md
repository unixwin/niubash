- Environment notes that shape everything below:
  - GitHub was unreachable all run (`schannel: failed to receive
    handshake`) — per AUDIT-PLAN rule 10 that is environment, not a
    finding. All network-dependent surfaces (collection clones, source
    adds) were pinned through the product's OWN mirror channel
    (§14.8 insteadOf, `NIU_MIRRORS`) to local fixture git repos with
    byte-faithful upstream layouts (`fixtures.py`). The registry/spec
    keep canonical GitHub URLs; only the transport is local.
  - **Probe-channel limitation 1 (Ctrl+C):** the pywinpty byte bridge
    cannot deliver 0x03 as a Ctrl+C *key event* to a raw-mode menu. A
    single `\x03` behaves as Enter-equivalent (the menu CONFIRMS its
    highlighted default and the flow advances; no cancelled note, no
    abort). Arrows/digits/Enter/Esc all deliver correctly. Evidence:
    `m06-ctrlc-channel/transcripts/m06-ctrlc-raw.txt`. The Ctrl+C
    *abort* paths (menu-level) are therefore UNVERIFIED in this lane —
    not a product finding, a channel limitation; needs a Windows
    Terminal/manual pass or a different injection path.
  - **Probe-channel limitation 2 (exit flush):** output written in the
    final moments before process exit is intermittently dropped by the
    channel — demonstrated 2/5 trials in a trivial non-niu child
    (`control-exit-flush.txt`, per-trial delivery `[9, 12, 11, 12, 12]`
    of 12 lines). This is why `niu setup`'s finish-screen tail looked
    truncated: durable state (journal written, backup written, exit
    code 0) proves the code path completed. Receipts of EXITING runs
    are asserted from the journal; first-contact runs (REPL alive)
    assert the on-screen receipts verbatim.

### L02-1 (P2) — "Undo this run" is incomplete on a fresh install: the wizard's own rc write and adopted loader blocks have no receipt and no undo path

- One-line: on a fresh install the finish screen's undo receipts cover
  the theme pick and the collection sources, but the rc write itself
  (no previous rc → no backup → no `cp` line) and at least one adopted
  rc managed block are not undoable — after running every printed
  receipt, a generated rc + `.setup-done` marker + an orphan guarded
  block remain.
- Repro (offline, fixture mirror):
  `python scripts/audit/wt82-L02/run_l02.py <niu> --only m01`
  → full walk (full collection → trust both → pick robbyrussell) → run
  each printed undo line verbatim →
  `cat $HOME/.niubashrc` still ends in a
  `# >>> niu source bash-it (managed by \`niu plugin enable/disable\`) >>>`
  block whose tree was just deleted by
  `niu plugin source remove bash-it`; `.setup-done` still present.
- Expected (the product's own promise): §0 iron law 3 — "every wizard
  write is reversible"; the finish screen header says "Undo this run:".
- Actual: every receipt exits 0 and does exactly what its comment says
  (verified), but the run's largest write — the rc — is not covered on
  a fresh install (there is no previous rc to back up, and no receipt
  removes the generated rc or the marker), and the bash-it loader block
  that the run landed in the rc is not receipted at all. No data loss
  (the block is guarded `[ -r … ]` and inert; startup stays quiet), so
  P2, not P1.
- Raw evidence: `m01-full-trust-pick/verdict.txt` ("disable removed the
  theme block from rc" detail shows the surviving bash-it block AFTER
  all receipts ran), `m01-full-trust-pick/transcripts/m01-undo-run.txt`,
  `m01-finish-screen.txt`.
- Suspected owner (read-only attribution):
  `setup_undo_lines()` `crates/niubash-runtime/src/setup_wizard.rs:125`,
  `print_finish_screen()` `:1602`; the orphan block writer is in the
  enable/selection path (`plugins/assets.rs` / `plugins/sync.rs` —
  wt71-hot, left untouched).
