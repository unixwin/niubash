# 2026-09-08

- 完成 niubash 对标 ZSH 的差距分析，产出 `docs/planning/niubash-zsh-gap-analysis.md`。
- 核心结论：rubash 语言引擎不是缺口（86/86 上游测试，read/mapfile/getopts/assoc/extglob/select 均已实现）；真正缺口在交互层。`rubash/src/builtins/bind.rs` 是兼容空壳（打印 "line editing not enabled"，不绑定任何键），导致用户无法绑键、无法写 widget，这是 P0。补全系统有 TOML/bash 导入/-h 抓取骨架但缺用户脚本级 compdef（P1）。钩子（precmd/preexec/chpwd）在 config.rs 已有数组，基本达标。生态开放度已有审计文档与 P0-P3 路线，待落地。
- 落地顺序：P0 Widget ABI（bind 真实现 + reedline 让位原语 + NIU_WIDGET_BUFFER/CURSOR/RESULT 环境变量契约）→ P1 用户补全契约（compdef + 菜单选择升级）→ P2 生态 git-url 通道 → P3 细节抛光（periodic、多行历史、保持 ~170ms 冷启动预算）。
- 追查确认：reedline 0.33 已内置 ExecuteHostCommand 挂起/恢复机制（engine.rs 挂起状态机 + current_buffer_contents + run_edit_commands 公开 API），Nushell 的 executehostcall 正是走这条路；niubash repl.rs 已有 bindkey 元数据 → 内置 widget 映射（native_widget_event），缺口仅是映射封闭、无 shell 函数逃逸通道。P0 设计改为：NIU_BINDKEYS（~/.niubashrc 纯 bash）→ 未知 widget 名 → ExecuteHostCommand("__niu_widget <name>") 哨兵 → 宿主执行函数（NIU_WIDGET_BUFFER/CURSOR 进、NIU_WIDGET_RESULT/ACCEPT 出）→ run_edit_commands 应用 → 编辑器恢复现场。不 fork reedline、不动 rubash（bind 空壳保留 bash 非交互语义）。用户明确拒绝 ZSH 兼容；fish/PSReadLine/nushell/elvish 也均未克隆 ZLE，都选了"编辑器事件 + 窄宿主 API"。设计已写入 docs/planning/niubash-zsh-gap-analysis.md。
